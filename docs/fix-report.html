Fix report: Huddle Notes

Security and sign-in review
Next.js + Supabase · October 2026

Summary. Before this work, anyone on the internet could read, change or delete every user's notes without logging in, and the app handed every visitor a key that controls the whole database. Both problems are fixed, along with sign-up and error handling. Privacy is now enforced by the database itself, and 15 automated tests check it on every change.

Three things still need you: replace the leaked key and update two settings in Supabase (see "What you need to do").

How you know it works

  • The same 15 tests were run before and after. Before: 4 passed, 11 failed. After: 15 passed.
  • Five of them act like an attacker: they skip the website and ask the database directly, using a second user's login or no login at all. They pass only when the database refuses.
  • The tests run automatically on every future code change, so this cannot quietly break again.
  • Everything that worked before still works: logging in, writing, editing and deleting your own notes, deleting your account.

What you need to do

  1. Replace the leaked key. In Supabase, generate a new service-role key and save it as SUPABASE_SERVICE_ROLE_KEY on your host. The old one was public, so it must be treated as stolen.
  2. Set your site address in Supabase under Authentication → URL Configuration, so email links point to your site.
  3. Paste the new confirmation email (included) under Authentication → Email Templates.

What changed for your data

No notes were deleted. Any note that had no valid owner was moved to a locked holding table (notes_orphaned) for you to review, because it could not safely be shown to anyone.

Not covered

Password reset (the app does not have one yet), limits on repeated login attempts, two-step login, and a review of your hosting settings. None are urgent; password reset is the one users will ask for first.
